# SYNERGY Production Readiness Runbook

> Этот документ описывает путь от исследовательской ветки к контролируемому production release.
>
> Текущий статус: прототип. Выполнение команд из этого файла само по себе не означает, что система готова принимать реальные средства.

---

## 1. Неподвижные правила эксплуатации

1. Не использовать private key, seed phrase или RPC secret, когда-либо опубликованный в чате, issue, pull request, log или shell history.
2. Не развёртывать все контракты репозитория. V2–V7 и test/fork harnesses являются разными поколениями.
3. Не считать model/fork profit гарантией live revenue.
4. Не включать QE, QT, dividend или bridge до регистрации всех системных адресов в boundary registry.
5. Не признавать revenue без фактического внешнего balance delta.
6. Не исполнять route, если его полный token path, costs и post-trade balance не проверяются атомарно.
7. Не использовать caller-supplied oracle как единственный источник цены.
8. Не использовать публичный mempool для чувствительных сделок без осознанного риска и жёстких limits.
9. Не продолжать работу при failed invariant, stale oracle, bridge outage или недостаточном gas reserve.
10. Не скрывать loss, pause, skipped action или failed transaction.

# 2. Среды

## 2.1. Local deterministic

Назначение:

- compile;
- unit tests;
- deterministic simulations;
- mock integration;
- fuzz/invariant development.

Не использует реальное chain state.

## 2.2. Pinned Polygon fork

Назначение:

- проверить реальный bytecode и token behavior;
- проверить QuickSwap/Aave addresses;
- повторить конкретное состояние блока;
- выполнить adversarial fixture.

Разрешены test-only impersonation и local funding. Полученные адреса локальных contracts/pools не являются mainnet addresses.

## 2.3. Shadow mode

Off-chain services читают реальные рынки, строят routes и сохраняют predicted result, но не отправляют сделки.

Цель: измерить false positives, quote decay, gas, slippage, oracle disagreement и MEV exposure.

## 2.4. Canary mainnet

Минимальный капитал, один settlement asset, жёсткий daily notional, private relay, ручной go/no-go и automatic pause.

## 2.5. Controlled production

Разрешается только после security/legal/operational gates и успешного canary period.

# 10. Required V7 hardening before deployment

Baseline V7 не допускается в production без следующих изменений.

## 10.1. Token route proof

Добавить в proof:

```solidity
address[] tokens; // length = pools.length + 1
```

Проверять:

- `tokens[0] == settlementAsset`;
- `tokens[last] == settlementAsset`;
- каждый pool действительно соединяет `tokens[i]` и `tokens[i+1]`;
- no repeated pool;
- ограничения repeated tokens/cycles явно определены.

## 10.2. Atomic execution

Proof gate должен вызывать bounded executor либо быть частью executor.

Не доверять declared `amountOut`.

Измерять:

```text
settlement balance before
settlement balance after
real pool/token balance deltas
flash repayment
actual gas policy charge
actual protocol-owned LP loss
```

## 10.3. Independent oracle

Не принимать caller-supplied `oracleOut` как единственный truth source.

Рекомендуется:

- Chainlink/TWAP/M-of-N;
- max age;
- confidence/deviation bound;
- sequencer/network checks, где применимо;
- fallback only through explicit mode;
- oracle source recorded in event.

## 10.4. Private execution

- private transaction relay;
- builder/bundle fallback policy;
- short deadline;
- one-time nonce;
- no public reveal before private submission;
- abort when quote deteriorates;
- post-trade validation.

## 10.5. Production depth

Fork-test minimum `1` base unit заменить на thresholds, рассчитанные из:

- maximum trade;
- allowed price impact;
- token decimals;
- reserve volatility;
- exit concentration;
- 24h stress withdrawal.

# 11. Governance deployment

Рекомендуемый порядок:

1. создать hardware-wallet-backed multisig;
2. создать timelock;
3. deploy contracts из fresh deployment wallet;
4. transfer admin в timelock/multisig;
5. назначить guardian с pause-only правами;
6. назначить bounded reporter/attester/operator;
7. revoke deployment wallet;
8. проверить каждый role on-chain;
9. выполнить time-delayed no-op policy update;
10. провести emergency pause drill.

Нельзя использовать один hot EOA одновременно как treasury, admin, keeper, oracle reporter и attester.

Минимальный рекомендуемый период: 30–90 дней, включая разные market regimes.

Каждая opportunity записывает:

```json

  "observed_at": "timestamp",
  "block": 0,
  "route_tokens": [],
  "route_pools": [],
  "amount_in": "0",
  "quoted_amount_out": "0",
  "oracle_amount_out": "0",
  "estimated_gas": "0",
  "pool_fees": "0",
  "slippage": "0",
  "flash_premium": "0",
  "internal_value_loss": "0",
  "predicted_net_profit": "0",
  "quote_after_1_block": "0",
  "quote_after_3_blocks": "0",
  "would_execute": false,
  "reject_reason": ""
}
```

Shadow review:

- false-positive rate;
- median quote decay;
- p95 gas error;
- p95 slippage error;
- opportunity duration;
- public/private inclusion comparison;
- oracle disagreement;
- concentration by pool;
- negative-tail outcome.

Production parameters должны основываться на shadow evidence, а не только на synthetic model.

Пример policy framework, не готовые численные рекомендации:

```text

one private relay
no cash dividend

bridge disabled initially
```

Повышение лимита требует:

- minimum number successful cycles;
- no unexplained balance delta;
- realised vs predicted error within threshold;
- no oracle/bridge incident;
- stable gas coverage;
- governance timelock;
- signed risk report.

# 17. Automatic pause conditions

Минимальный набор:

```text
oracle stale or disagreement above cap
bridge unavailable when route depends on it
solvency below defensive floor
liquidity below floor
gas coverage below floor
negative or unexplained balance delta
external net profit <= minimum margin
exit depth below threshold
unexpected public local-token pair/activity
commit/reveal anomaly
replay attempt
role or bytecode change outside scheduled governance
ledger/sourceId inconsistency
monitoring unavailable
```

Pause должен запрещать новые risk-increasing actions. Recovery/QT path должен быть отдельно определён; нельзя автоматически разрешать любой QT под предлогом recovery.

# 18. Incident runbooks

## 18.1. Negative realised PnL

1. pause new execution;
2. record loss in ledger;
3. reconcile every balance;
4. identify gas/slippage/oracle/internal LP component;
5. prohibit QE masking;
6. recompute solvency;
7. publish incident summary;
8. resume only after governance review.

## 18.2. Oracle incident

1. pause routes using source;
2. compare independent sources;
3. preserve raw observations;
4. disable dividend/QE;
5. update source only via governance;
6. replay shadow simulation;
7. unpause after fresh bounded observations.

## 18.3. Bridge incident

1. mark bridge unavailable;
2. stop dependent operations;
3. keep pending amount as bridge exposure, not settled asset;
4. track refund/fill deadline;
5. reconcile destination receipt;
6. do not issue new claims against pending funds.

## 18.4. Key compromise

1. emergency pause;
2. revoke role;
3. rotate providers and credentials;
4. transfer custody to fresh multisig;
5. inspect approvals and pending timelock actions;
6. consider compromised key permanently unsafe;
7. publish on-chain remediation references.

## 18.5. Public pool attack

1. stop public route;
2. compare spot/TWAP/external pools;
3. reduce or cancel pending commits;
4. inspect liquidity/price impact;
5. record realised loss;
6. use private relay when resuming;
7. do not confiscate unrelated addresses without objective contractual bond violation.

# 20. Rollback semantics

Immutable blockchain deployment нельзя «откатить» как обычный сервер.

Возможные действия:

- pause;
- revoke operator;
- remove route/pool from allowlist;
- reduce limits;
- migrate balances;
- deploy corrected module;
- timelocked governance transition;
- deprecate old frontend/keeper;
- redeem liabilities;
- publish migration proof.

Upgrade proxy допустим только при отдельно аудированной governance model. Не добавлять upgradeability автоматически ради удобства.

# 24. Финальное правило оператора

При сомнении система должна не торговать.

Упущенная возможность — ограниченный потенциальный доход. Ошибочно признанная прибыль, потеря резерва или выпуск необеспеченного обязательства способны разрушить всю систему.

Поэтому production SYNERGY должна быть построена по принципу:

> Fail closed, account globally, measure externally, execute atomically, scale gradually.
